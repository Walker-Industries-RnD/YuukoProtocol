3 - Shared Documents

SimpleCRDT (DOGMA I). Documents that every device can edit at any time, even offline, and that merge into the same result everywhere. There is no owner and nothing to resolve: use it for settings, lists and reminders.

A document holds named text fields called labels. Changes are sent as they happen, and two devices that meet swap whatever the other is missing.

Functions

Function What it does
SimpleCRDT.Start() Turns on sync with every connected device. Once, after Identity.CreateNode
SimpleCRDT.NewDoc() A new empty document id. Always use this, never new Doc() (see below)
SimpleCRDT.CreateNewDoc(doc) Shares a document with every connected device
SimpleCRDT.RemoveDoc(uuid) Removes it everywhere (only the device that made it, unless you change that)
SimpleCRDT.SyncAll() Compares notes with every connected device now
SimpleCRDT.ItemList The documents this device has, by UUID
new SharedDocs(DeviceName, LabelName, LastUpdated, Data) Makes a document (Data can be null)
doc.CreateLabel(Label, Content) Adds a label with a first text
doc.CreateText(Label, Content) Adds text at the end of an existing label
doc.AddToLabel(Label, Content, Overwrite) Adds at the end, or replaces the whole label when Overwrite is true
doc.ReadLabel(Label) / doc.ReadDoc() Reads one label / all of them
doc.DeleteFromLabel(Label, StartingPoint, EndPoint) Removes part of a label
doc.NukeLabel(Label, DeleteLabel) Empties a label (and removes it if DeleteLabel)

More options on the sync itself, through SimpleCRDT.Start() (it gives back the DocSync):

Member What it does
AnyMemberMayRemove Let any device remove a document (default: only the one that made it)
AntiEntropyInterval How often devices compare notes by themselves (default 20 seconds)
DocReceived(doc) A new document arrived
DocUpdated(doc, fromDevice) An existing one changed because of another device
DocRemoved(uuid, byDevice) One was removed
Problem(device, message) Something was refused

Example: a shared list

//On the pc
SimpleCRDT.Start();

var List = new SimpleCRDT.SharedDocs("pc", "Shopping list", DateTime.UtcNow, null);
List.CreateLabel("items", "milk\n");
await SimpleCRDT.CreateNewDoc(List);        //every connected device gets it
List.AddToLabel("items", "eggs\n");         //and every change after this is sent by itself

//On the phone
SimpleCRDT.Start().DocReceived += Doc => Console.WriteLine("Got " + Doc.LabelName);

//Later
var List = SimpleCRDT.ItemList.Values.First(d => d.LabelName == "Shopping list");
Console.WriteLine(List.ReadLabel("items"));     // milk, eggs
List.AddToLabel("items", "bread\n");            //the pc sees this too

If the phone is offline and edits, then comes back, both sets of edits end up in the document. Nothing is lost.

Example: one setting (a theme)

Use a label that is replaced each time. Create it on one device; the others receive it.

//On the first device, once
var Settings = new SimpleCRDT.SharedDocs("laptop", "settings", DateTime.UtcNow, null) { UUID = "xruios.settings" };
Settings.CreateLabel("theme", "Whisper");
await SimpleCRDT.CreateNewDoc(Settings);

//Any device: change it
SimpleCRDT.ItemList["xruios.settings"].AddToLabel("theme", "Midnight", Overwrite: true);

//Every device: react to changes
SimpleCRDT.Start().DocUpdated += (Doc, From) =>
{
    if (Doc.UUID == "xruios.settings") ApplyTheme(Doc.ReadLabel("theme"));
};

If two devices change it at the same moment, the label ends up holding both values joined together. For a single value that must be exactly one, store the time with it and ignore the older one, or use a command (see 7 - Commands and Devices).

Example: editing part of a label

Doc.CreateLabel("notes", "Hello world");
Doc.DeleteFromLabel("notes", 5, null);          // "Hello"  (null means to the end)
Doc.DeleteFromLabel("notes", 0, 2);             // "llo"
Doc.NukeLabel("notes");                         // empty, the label stays
Doc.NukeLabel("notes", DeleteLabel: true);      // the label is gone

Example: removing

await SimpleCRDT.RemoveDoc(List.UUID);         //removed on every device and can't be shared again

SimpleCRDT.Start().AnyMemberMayRemove = true;  //now any device can remove any document

Things to know

  • Never make a document with new Doc(). YDotNet's default ids collide about 6 in 100 times and two devices with the same id silently corrupt each other's text. SimpleCRDT.NewDoc() (used by SharedDocs) makes a safe one.
  • Text only. A label is text, not a list or a number: store those as text.
  • There is no "newest wins". LastUpdated is for showing.
  • A device that removes a document it never saw is ignored: nobody can block a real document by claiming it was removed.

Limits, big documents and many documents

Nothing is limited unless you say so. These are settings, on SimpleCRDT:

Setting Default What it does
SimpleCRDT.MaxDocs no limit How many documents this device keeps. At the limit, sharing a new one throws and one sent by another device is refused (Problem)
SimpleCRDT.MaxLabels 256 How many labels (text fields) one document may have
SimpleCRDT.ChunkBytes 500 KB A change bigger than this is sent in pieces of this size
SimpleCRDT.MaxChunkedBytes 128 MB The biggest thing that is put back together, so another device can't fill your memory by promising a huge one 
SimpleCRDT.MaxDocs = 5000;                    //only if you want a limit
SimpleCRDT.MaxChunkedBytes = 1L << 30;        //allow documents up to 1 GB

A document can be any size. One message holds about 700 KB, so a bigger announce, update or push is cut into pieces (crdt.chunk), sent in order, and put back together on the other side. A hash of the whole thing is checked at the end, and pieces that don't fit together, claim to be more than they said, or come for a message that can't be sent in pieces are refused. One device can only have 4 of them being put back together at once, and ones that stop coming are forgotten after 2 minutes.

A device can have any number of documents. The list of documents is compared in pages of about 200 KB, and the list of removed ones a page at a time, so the number of documents is not limited by the size of one message. The data that doesn't fit in one answer is sent after it.

Things to know:

  • A big document is held in memory in full (Yjs keeps its history), so the real limit is your device's RAM, not these settings.
  • Pieces go to the devices you are directly connected to, and they pass on what is new to them.
  • Removed documents are remembered forever (so they can't come back), and that list grows.
