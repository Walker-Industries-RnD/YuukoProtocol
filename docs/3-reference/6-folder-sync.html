6 - Folder Sync

DAG (DOGMA IV). The same folder on every device that shares it. Only what changed is sent, a download that stops carries on where it stopped the next time you sync, and nothing is put in place until it is checked.

DAG.cs is the encrypted repository of the folders this device shares (the CRUD part), DAG.Sync.cs is the sync.

Functions

Function What it does
DAG.Start(key) Loads the repository and starts answering other devices. Once, after Identity.CreateNode
DAG.ShareFolder(DirectoryPath, Devices) Shares a folder from this device. Gives back an entry with the UUID the others join with
DAG.JoinFolder(UUID, DirectoryPath, Devices) Joins a folder another device shared: same UUID, your own path (files already there are kept)
DAG.CheckIfFolderExists(Device, UUID) Does that device share this folder with us?
DAG.CheckForUpdate(Device, UUID) Does it have something different from us? (changes nothing)
DAG.SyncFolder(Device, UUID) Gets what that device has. Gives back what happened
DAG.ResumeFolder(Device, UUID, Tries) The same, and if some files failed it waits a second and syncs again (3 tries by default), so a sync that stopped half way is pushed to the end
DAG.BroadcastUpdate(UUID) Tells every connected device this folder changed here, the ones that share it come and get it
DAG.StopSharing(UUID) Stops sharing on this device (the files stay)

What SyncFolder gives back (SyncResult): Downloaded, Deleted, Conflicts (list of paths), Errors (list), AlreadyInSync, LocalChanges (we have things they don't).

Settings and events:

Member What it does
DAG.AutoSync Sync by itself when a device says a folder changed, or when a listed device connects (default on)
DAG.AllowMassDelete Let one sync delete almost everything (default off, see below)
DAG.RepoPath Where the encrypted repository is saved (default: LocalAppData/YuukoProtocol)
DAG.LastSync What the last sync of each folder did, by UUID
DAG.FolderUpdated(UUID, fromDevice, result) A sync changed something here
DAG.Progress(UUID, path, bytesDone, bytesTotal) A file is being downloaded
DAG.Problem(message) Something failed in the background

The repository calls (yours): InitializeRepoFile, SetupRepo, CreateNewEntry, GetAllEntries, GetSpecificEntry, GetSpecificEntryByDirectoryPath, UpdateVariable, UpdateVariableByDirectoryPath, DeleteVariable, DeleteVariableByDirectoryPath, ReturnIfFolderExists. ShareFolder, JoinFolder and StopSharing use them for you.

Example: share a folder and get it on another device

//On the pc
var RepoKey = new SecureData(Encoding.UTF8.GetBytes("the repository password"));
await DAG.Start(RepoKey);

var Folder = await DAG.ShareFolder(@"D:\Movies", new List<string> { "phone" });     //these are the devices allowed to have it
Console.WriteLine(Folder.UUID);        //give this to the phone: type it, show it, or send it in a command

//On the phone
await DAG.Start(RepoKey2);

await DAG.JoinFolder(UUIDFromThePc, "/storage/Movies", new List<string> { "pc" });

DAG.Progress += (UUID, Path, Done, Total) => Console.WriteLine($"{Path}: {Done * 100 / Total}%");

var Result = await DAG.SyncFolder("pc", UUIDFromThePc);
Console.WriteLine($"{Result.Downloaded} files, {Result.Deleted} deleted, {Result.Conflicts.Count} conflicts, {Result.Errors.Count} errors");

From now on, either device can change files and tell the other:

//After changing files on the pc
await DAG.BroadcastUpdate(Folder.UUID);        //the phone syncs by itself

Example: check first, then sync

if (!await DAG.CheckIfFolderExists("pc", UUID)) return;           //not shared with us
if (await DAG.CheckForUpdate("pc", UUID))
{
    var Result = await DAG.SyncFolder("pc", UUID);
    if (Result.Errors.Count > 0) foreach (var Problem in Result.Errors) Console.WriteLine(Problem);
}

Example: finding out what changed

DAG.FolderUpdated += (UUID, From, Result) =>
    Console.WriteLine($"{From} changed {UUID}: {Result.Downloaded} new, {Result.Deleted} deleted, {Result.Conflicts.Count} conflicts");

DAG.Problem += Message => Console.WriteLine("Sync problem: " + Message);

Example: stopping

await DAG.StopSharing(Folder.UUID);         //this device stops. The files stay where they are

How it decides what to do

A sync compares three things for every file: this device, the other device, and what both agreed on last time.

What happened Result
Only they changed it We get it
Only we changed it Nothing now. We tell them and they come and get it
They deleted it, we didn't touch it It's moved to .yuuko/trash here
We deleted it, they didn't touch it They delete it when they sync
Both changed the same file The newest wins on both devices, the other is kept beside it as name (conflict 1a2b3c4d).ext
One deleted it, the other changed it The changed one stays

The conflict name is made from the file's own content, so both devices make the same name and a conflict never multiplies. Both devices end up with the same files.

Things to know

  • Safety. A device only gets files from folders it is listed for, and only files that are in the folder's own list. A path another device sends is never used as it is (nothing that climbs out of the folder, nothing in .yuuko, nothing through a shortcut).
  • A folder that isn't there (an unplugged drive) is an error, not an empty folder, and a sync that would delete nearly everything (more than 10 files and over half) refuses unless AllowMassDelete is on.
  • Deleted files go to .yuuko/trash/<time>/, never erased. Half-downloaded files wait in .yuuko/partial/. Both are inside the shared folder but never shared.
  • The first sync of a big folder reads every file once to hash it.
  • The device names in the Devices list must be the names the other devices call you ("pc", "phone").
  • Pairing builds the node again: after Identity.NodeRestarted, call DAG.Start(key) again.

Limits, many files and big files

Nothing is limited unless you say so (it used to stop at 4000 files and 4 GB per file):

Setting Default What it does
DAG.MaxFiles no limit A folder with more files than this can't be listed
DAG.MaxFileBytes no limit A file bigger than this is left out of the folder 
DAG.MaxFiles = 100_000;          //only if you want a limit
DAG.MaxFileBytes = 20L << 30;    //20 GB
  • Many files. The list of files is asked for a page at a time (about 500 KB each), from a list that is kept still while the pages are given, so a folder of any size is listed. If the other device's folder changes between two pages, the list is asked for again from the start (up to 3 times). A list that doesn't move forward, goes back, names a bad path or a bad hash, or has more than your limits, is refused as a whole.
  • Big files. A file is sent in 256 KB pieces and the places in it are 64-bit, so there is no size at which it stops. A download that stops carries on where it was in a later sync (see below).
  • Tested with 4100 files syncing between two devices. A file of 4.5 GB was listed, hashed and read at a place past 4 GB, but a whole transfer of a file that big has not been run. Reading and hashing a big file takes as long as the disk takes to read it, on both devices.

A sync that didn't finish: you push it on

Nothing starts a stopped sync again by itself. A sync reports what failed in SyncResult.Errors and carries on with the other files; the next sync fetches only what is still missing, and a file that was half downloaded carries on from the last whole 256 KB piece (it waits in .yuuko/partial/ under its hash, and is checked in full before it is put in place). So your app decides when to try again:

var Result = await DAG.ResumeFolder("pc", FolderUUID);       //syncs, and while files failed waits a second and syncs again (3 tries)
if (Result.Errors.Count > 0) Console.WriteLine("Still not done: " + Result.Errors[0]);
  • ResumeFolder adds up what the tries downloaded and deleted, and hands back the last try's errors. It throws if the other device can't be reached at all.
  • The usual places to call it: when a device connects (Identity.YuukoNode.PeerConnected), on a timer, or before you tell the user the folder is up to date (DAG.LastSync[FolderUUID].Errors).
  • DAG.AutoSync (on by default) starts one sync when a listed device connects or says a folder changed, but doesn't retry it: that is what ResumeFolder is for.
  • A file that changes on the other device while you download it leaves its old half-copy behind in .yuuko/partial/. Nothing cleans those up yet.
