3 - TLS and the Link

Yuuko devices talk to each other over Zenoh. TLS and mutual TLS are on by default for that connection. This page explains what that does, what it doesn't, and where the files are.

TLS 1.3

The connection is set up to use TLS 1.3 whenever both devices support it, and to fall back to TLS 1.2 only if one of them can't do 1.3. (That's what the transport's code says it does. I haven't captured a real connection to check which version was used, and it has only been run on one machine.)

"Mutual" means both sides show a certificate. Each device has one, signed by the group's certificate authority. A device that can't show a certificate from an authority this device trusts is turned away before a single Yuuko message is read.

What TLS gives you

  • Hides who talks to whom. On the network, an outsider sees an encrypted connection, not device names, message sizes or timing inside it.
  • Keeps strangers from starting a handshake. The expensive part (the Yuuko handshake) never runs for a device without a certificate. That is the first defence against someone flooding a port.
  • Stops the easy mistakes. With TLS on there is no automatic discovery on the local network, because discovery would have shown a device's presence to anyone. Devices find each other through the address in a pairing code, or addresses you list.

What TLS does not give you

  • It doesn't say which device is which. The certificate says "a member of this group". What proves a device is the one you pinned is the Yuuko handshake and its fingerprints.
  • It isn't what protects your data. TLS only covers one hop, between two neighbouring devices. The messages are sealed again by the Yuuko handshake (AES-256-GCM, with a fresh throw-away key) from device to device, so the data is encrypted twice. If TLS were broken, the Yuuko layer is still there. If a device relays a broadcast, it can read it and can't change it (see 1 - Security Overview).
  • It doesn't make the group key unnecessary. See 2 - The Group Key.

The group's authority

  • The first device's certificate authority becomes the group's. When a device pairs, the one that offered the pairing hands over the authority (certificate and key) over the encrypted session, and the newcomer makes itself a certificate from it. From then on everyone trusts the same single authority, so adding a device never means updating the others and nobody has to restart.
  • Because every member holds the authority's key, a stolen member could make certificates. That only gets someone past the TLS layer. The handshake still has to succeed, and removing a device from the group (Identity.UntrustDevice, KickDevice) is how you shut it out.
  • A device that already has paired devices of its own will not leave them to join a different group. It refuses.

How a new device gets in the first time

Mutual TLS would turn a newcomer away, so the pairing code carries a temporary certificate for it alone, valid for the pairing window plus two minutes. After pairing the newcomer has to open its connection again to switch to its permanent one (Identity.ConnectToDevice builds the node again for this, but that hasn't been tried over a real network yet). Until then it uses the temporary one, which stops being accepted for new connections after a few minutes.

The pairing code carries that temporary certificate and its key, so treat the code as a secret until it is used or expires. Anyone who sees it (a shoulder-surfed screen, a photo) can pair in that window.

Where the files are

%LOCALAPPDATA%/YuukoProtocol/tls/<device name> (or the folder you set as TlsDirectory):

File What it is
ca.pem / ca.key The group's certificate authority (10 years)
cert.pem / key.pem What this device shows (1 year, renewed by itself)
trust.pem The authorities this device trusts
  • Zenoh needs the keys as files, so they are plain PEM, not password-protected. Anyone who copies one can pretend to be that device at the TLS layer only. They still can't pass the handshake. On Linux the folder is made owner-only; on Windows it sits under your profile, so protect your profile.
  • A device's trust list is read when the connection opens. It changes when the device joins a group while pairing, or when you call YuukoTls.TrustPeer yourself.
  • YuukoTls.Check(folder, name) tells you the state of a device's certificates without changing anything: Missing, Valid, ExpiresSoon, Expired or Invalid.

Turning it off

You can (EnableTls = false). Then LAN auto-discovery comes back and the connection's metadata (who talks to whom, sizes, timing) is visible to anyone on the network. The messages themselves are still sealed by the Yuuko handshake. There is rarely a reason to do this outside a test.

Ports

If you don't name a port, the transport listens on the first free port from 7447 and tells you which (transport.ListenEndpoints). Make sure your firewall lets the app through; the pairing code carries the address.
