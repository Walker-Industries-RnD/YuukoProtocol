3 - Setting Up A Project

How to start a new project that uses Yuuko Protocol, from nothing to a device that is up and showing a pairing code. Every step here was run on a brand new project, and the program at the end is the one that was tested.

When it works, 2 - Quickstart shows what to do with it and 0 - All Functions lists every call.

What you need

You need Why
The .NET 8 SDK The library is C# on .NET 8. dotnet --list-sdks should show an 8.x
The Yuuko Protocol code It isn't a NuGet package yet: your project points at it
Internet, once The first build downloads Zenoh's native library (zenoh-c 1.6.2, about 15 MB) and everything else comes from NuGet

You do not install anything else. The Pariah and Eclipse DLLs it needs are in the repo's libs folder, and the packages it depends on (Zenoh-CS, YDotNet, Argon2, BouncyCastle...) are restored by the build.

On Linux, install libgdiplus too if you want app icons from 5 - Apps and Icons.

1. Put the code next to your project

git clone https://github.com/Walker-Industries-RnD/YuukoProtocol.git
dotnet new console -n MyApp

You end up with this (the names that matter are the three marked):

Projects/
  YuukoProtocol/                    the clone
    YuukoProtocol/                  the solution folder
      YuukoProtocol/                 the library project              <- (1) YuukoProtocol.csproj
      libs/                          Pariah and Eclipse DLLs          <- (2) PariahCybersecurity.dll
      ZenohNative.targets            gets Zenoh's native library      <- (3)
  MyApp/                            your project

2. Point your project at it

Replace MyApp.csproj with this (three lines are Yuuko's, marked):

<Project Sdk="Microsoft.NET.Sdk">

  <!-- (3) Fetches the native Zenoh library for this machine on build and copies it next to your program -->
  <Import Project="..\YuukoProtocol\YuukoProtocol\ZenohNative.targets" />

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

  <ItemGroup>
    <!-- (1) The library -->
    <ProjectReference Include="..\YuukoProtocol\YuukoProtocol\YuukoProtocol\YuukoProtocol.csproj" />
  </ItemGroup>

  <!-- (2) SecureData, the type the passwords are in, lives in Pariah -->
  <ItemGroup>
    <Reference Include="PariahCybersecurity">
      <HintPath>..\YuukoProtocol\YuukoProtocol\libs\PariahCybersecurity.dll</HintPath>
    </Reference>
  </ItemGroup>

</Project>

Leave the Import out and the program builds but can't open a connection: the native library never reaches your output folder.

3. The program

This is Program.cs. It makes a device called pc, starts it, makes a pairing code, and stops.

using System.Text;
using WISecureData;
using YuukoProtocol.Dogma;

var Me = "pc";                                   //"phone" on the other device

//Passwords are SecureData made from bytes (NOT SecureData.FromString, it wipes the string you give it)
var DeviceKey = new SecureData(Encoding.UTF8.GetBytes("this device's own password"));    //locks the identity file, 8 characters or more
var ListKey = new SecureData(Encoding.UTF8.GetBytes("password for the saved device list"));
var FileKey = new SecureData(Encoding.UTF8.GetBytes("password for the reconnect file"));

//Put the Start calls here: this runs once the node is up, and again every time pairing builds it again
Identity.NodeRestarted += async (s, e) =>
{
    await Reconnect.Start();                     //paired devices find each other again after they were off
    //SimpleCRDT.Start(); OpTransform.Start(); HolyMother.Start(); await DAG.Start(RepoKey); Cogitarium.Start();   <- whatever you use
    Console.WriteLine("Node is up. Connected devices: " + Identity.ViewAllConnectedMachines().Count);
};

//Made ONCE for a new group, then the same one is typed into every other device (see below)
var GroupKey = Encoding.UTF8.GetBytes(Identity.CreateGroupKey());

Reconnect.Open(Me + "-reconnect.json", FileKey);          //BEFORE CreateNode
await Identity.CreateNode(DeviceKey, Me + ".id", Me, true, GroupKey, Me + "-devices.json", ListKey);

var Code = await Identity.CreatePairing();
Console.WriteLine("Pairing code: " + Code);

await Task.Delay(1500);
Identity.Shutdown();                              //when your app closes
Reconnect.Stop();

dotnet run --project MyApp

You should see:

Node is up. Connected devices: 0
Pairing code: YUUKO2-...

The code is long on purpose (about a thousand characters: it carries the address, a one-time token and a temporary certificate), so show it as a QR code rather than asking someone to type it.

The first build takes a little longer because of the Zenoh download.

What it made on disk

Run it from a folder you chose (these names are relative to it). Back up the first two and keep all of them out of git.

File What it is Keep it safe
pc.id This device's identity (its private keys). Locked with DeviceKey Yes: without it and the password the device would have to pair again
pc-reconnect.json This device's UUID, its fixed port and the paired devices' addresses. Encrypted with FileKey Yes
pc-devices.json The paired devices and their keys. Made when you pair the first one. Encrypted with ListKey Yes
%LOCALAPPDATA%\YuukoProtocol\tls\pc\ This device's TLS certificate (on Linux ~/.local/share/YuukoProtocol/tls/pc/) Made for you
%LOCALAPPDATA%\YuukoProtocol\ Where DAG keeps its folder list (DAG.RepoPath) If you use folder sync

The names are yours to choose: DeviceID (the identity file), TrustedDevices (the device list) and the path in Reconnect.Open can each be a full path, and a name with no folder in front of it is the current folder.

4. A second device

Same project, run on the other machine with one change: Me is "phone" and the group key is the one from the first device, not a new one.

var GroupKey = Encoding.UTF8.GetBytes(TheGroupKeyText);       //typed in, scanned or read out, never sent over the group's own network

Then one device shows a code and the other types it:

//pc
var Code = await Identity.CreatePairing();                    //show it as text or a QR code
Identity.GroupChangeRequested += (s, e) => e.SetResult(true); //ask the user here instead

//phone
await Identity.ConnectToDevice(Code, "pc", "phone");

Check the fingerprint out loud the first time. More in 2 - Identity and 2 - The Group Key.

5. Turn on what you need

Each part is one Start call, in the NodeRestarted handler above:

You want Start it Page
Settings and lists that merge SimpleCRDT.Start() 3 - Shared Documents
A text several people type in OpTransform.Start() 4 - Shared Text
See and open apps on another device HolyMother.Start() 5 - Apps and Icons
The same folder on every device await DAG.Start(RepoKey) 6 - Folder Sync
Live streams between devices (the SCCN) Cogitarium.Start(), or await Nearby.Start() for strangers 8 - Collective Distribution
A record of what the device decided AuditLog.Open(...) 9 - Audit Log
Your own commands Identity.YuukoNode.On("name", handler) 7 - Commands and Devices

Pairing builds the node again, so the Start calls and your own On(...) handlers have to be in the handler, not after CreateNode.

6. Keep things going: you push, it doesn't push itself

Yuuko doesn't retry forever in the background. A call that asks another device can fail when that device is off, and a sync that stopped stays stopped until your app asks again. That's on purpose: your app decides when to try again.

//A folder sync that didn't finish: ask again. Files that arrived stay done, a half downloaded one carries on where it stopped.
try
{
    var Result = await DAG.ResumeFolder("pc", FolderUUID);           //syncs, and if some files failed waits a second and tries again (3 tries)
    if (Result.Errors.Count > 0) Console.WriteLine("Still not done: " + Result.Errors[0]);
}
catch (Exception ex) { Console.WriteLine("Couldn't reach pc: " + ex.Message); }

The usual places to do it:

  • When a device comes back: Identity.YuukoNode.PeerConnected += Peer => ... and call DAG.ResumeFolder for the folders you share with it.
  • On a timer, for devices that are on but unreachable.
  • Before you tell the user it is done: check DAG.LastSync[FolderUUID].Errors.

Two things do come back by themselves: paired devices that were turned off find each other again (Reconnect), and shared documents catch up (SimpleCRDT compares notes when a device connects and every 20 seconds).

Before you ship

  • Passwords: DeviceKey is 8 characters or more. The group key is 16 bytes or more and is kept like a password. Don't put either in your code or your repo.
  • Set HolyMother.Allow before other devices can open apps: until you do, it says yes to everyone.
  • The port: the node listens on one fixed port (saved in pc-reconnect.json, the first free one from 7447; if it is taken one day, another free one is chosen and saved). Allow it through the firewall on the local network. Reconnect (and Nearby) also open a separate plain link on a random port for their beacons, and nothing but beacons goes over it.
  • Same network: finding strangers (Nearby) and finding paired devices again (Reconnect) work on one Wi-Fi or LAN. Forming a Wi-Fi Direct group, or Bluetooth, is your app's job.
  • Files out of git: add *.id, *-reconnect.json, *-devices.json and .zenoh-native/ to .gitignore.
  • Platforms: Windows is what it has been tested on. Linux's app list and icons, Android and iOS have not been run.

When it doesn't work

You see It means
Create the node first (Identity.CreateNode) A Start call or Reconnect.Start() ran before CreateNode finished: move it into NodeRestarted
Call Reconnect.Open first Reconnect.Open(...) has to come before CreateNode
The node password has to be at least 8 characters DeviceKey is too short
Wrong password, or the identity file is damaged DeviceKey isn't the one the identity file was locked with
The program builds but fails to connect The ZenohNative.targets import is missing, or the first build had no internet. Delete .zenoh-native next to the targets file and build again
